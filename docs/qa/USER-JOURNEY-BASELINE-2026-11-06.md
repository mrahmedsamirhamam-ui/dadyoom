## أول دفعة منفصلة: /try
**المشكلة قبل التعديل:** انتقال مباشر إلى سؤالين منفصلين دون هدف ظاهر، شرح سابق أو مثال محلول، ودون سؤال تحقق بعد التعلم. كان عرض النتيجة قابلًا للفهم على أنه إثبات تعلم، لكنه غير كافٍ لإتقان مهارة.

**حل الفرع:** هدف واحد لتمييز الفعل، متطلبات سابقة، شرح ومثال، سؤالان موجهان، سؤال تحقق جديد مستقل، تفسير للإجابة الخطأ مع الإجابة الصحيحة، ملخص صريح لا يمنح إتقانًا أو شهادة، ومراجعة وإعادة محاولة وحساب اختياري للتقدم القادم. كل الإجابات تُدار محليًا في ذاكرة الواجهة؛ بلا تخزين نتائج أو بيانات أطفال.

**القبول التقني:** نجاح `vitest`, `tsc`, `eslint`, `next build`، ورحلة Chrome مع RTL وعدم تمرير أفقي على 360 و390 و430 و1280، ولقطات محفوظة كأثر اختبار. الفحص الآلي لا يعادل WCAG 2.2 AA يدويًا.

**خط التراجع:** التغيير معزول عن قاعدة البيانات والخدمات؛ لا دمج تلقائي. يمكن إغلاق PR أو عكس ملفي `app/try/page.tsx` و`lib/growth/guest-trial.ts` إذا فشل قبول الفريق.

## دفعات لاحقة مشروطة
- **P0** أمن الصلاحيات ونزاهة التقييم والنشر، ببيئة معزولة ونسخ احتياطية وموافقة قبل ترحيلات حساسة.
- **P1** دمج مراجعات الصفحة الرئيسية القائمة بعد فض التعارضات، اختبار تجربة /ask المحمية، تحديد الخطوة التالية وحفظ تقدم الطالب.
- **P2** متابعة الطالب والمعلم والأسرة والمدرسة وقاموس أحداث يتجنب بيانات الطفل، وبناء اعتماد محتوى موثق.
- **P3** التوسع الرسمي بعد تحقق فهارس الدولة ومراجعة المعلمين والتأكد من انضباط المصدر والترخيص.

التقدير التنفيذي غير التعاقدي: دفعة /try صغيرة (نحو يومين إلى أربعة عمل من تنفيذ ومراجعة واختبارات عند توفر CI)، لكن مدة P0 تعتمد على الوصول إلى بيئة الاختبار وموافقة مالك قاعدة البيانات. لا توجد حتى الآن نتائج مقابلات أو بيانات ميدانية عن الاحتفاظ أو الإتقان؛ لا تختلق خط أساس رقمي.
