# ضاديوم — فحص قبول بقاء الجلسة وبساطة التسجيل
التاريخ: 6 نوفمبر 2026. اختبار قبول مقرر، وليس إثبات اختبار متصفح حي.

## سلوك مطلوب

| السيناريو | النتيجة |
|---|---|
| عودة صاحب جلسة صالحة إلى / أو /login أو /signup | تحويل إلى /my ثم إلى لوحة الدور المخزن في profiles |
| طالب أو معلم يغادر الدرس | العودة إلى مساحته دون تسجيل خروج |
| زائر جديد أو جلسة منتهية | صفحة عامة ونموذج دخول عند الطلب |
| خروج صريح | إنهاء جلسة Supabase ثم عرض دخول |
| فشل الخروج | رسالة واضحة دون ادعاء نجاح |
| نموذج الدخول | بطاقة RTL واحدة، بريد وكلمة مرور وزر أساسي واحد |
| Google أو حساب جديد | خيارات مستقلة متباعدة أسفل النموذج |

## الفحص المطلوب قبل النشر

1. اختبار إغلاق المتصفح ثم فتحه على هاتف حقيقي مع جلسة موجودة؛ لا ينبغي ظهور تسجيل جديد.
2. اختبار الأدوار الستة بحسابات تجريبية مرخّصة وملفات شخصية مكتملة.
3. اختبار تجديد token وSet-Cookie عند الوصول إلى / و/login و/my عبر Cloudflare.
4. التأكد من انتهاء الجلسة فقط عند الضغط على تسجيل الخروج أو انتهاء صلاحية الإذن.
5. اختبار الرابط الفعلي لاستعادة كلمة المرور وGoogle OAuth بعد ضبط Redirect URLs.
6. اختبار الشاشات الضيقة والقارئ الصوتي والحقول واللمس؛ لا أزرار متكررة بجوار العنوان.
7. فحص خطأ ملف المستخدم والإنترنت الضعيف دون كشف جلسات أو بيانات أطفال.

## شروط حظر النشر

- Issue #117: تصعيد أدوار حسابات profiles عبر INSERT وUPDATE لا يزال يتطلب إصلاحًا واختبارًا في بيئة منفصلة.
- Issue #46: مشكلة Cloudflare والأمر الخاطئ للنشر لم تُغلق.
- الاختبارات الحالية Node وTypeScript وESLint لا تعادل الاختبار الحقيقي على المتصفح.
- لا كلمة مرور محفوظة يدويًا، ولا جلسة أبدية: انتهاء صلاحية التجديد أو حذف ملفات الارتباط يتطلبان الدخول مجددًا.

الحالة: فرع مراجعة فقط، دون نشر أو تحديث قاعدة بيانات الإنتاج.
