# حسابات تجريبية لكلود — تدقيق أدوار ضاديوم

هذه الآلية تخص **dadyoom.com** وليس مشروع مدارس ضاديوم الدولية DIS. الهدف أربعة مستخدمين مستقلين من دون أي صلاحية admin أو وصول لبيانات حقيقية.

## إعداد الحسابات

شغّل في جهاز المالك داخل مشروع ضاديوم بعد `npm ci`:

```bash
node scripts/provision-claude-qa.mjs
```

هذا معاينة فقط ولا يغير شيئًا. لإجراء الإنشاء الفعلي، اضبط `SUPABASE_URL=https://hvqsvtomhlxavmfqoxfz.supabase.co` و`SUPABASE_SERVICE_ROLE_KEY` **كأسرار على جهازك أو بيئة خادمية خاصة فقط**، ثم:

```bash
node scripts/provision-claude-qa.mjs --apply
```

يستخدم السكربت Supabase Auth Admin API لإنشاء مستخدم طالب ومعلم وولي أمر ومدرسة، مع عناوين اختبار محجوزة بنطاق `example.test` وكلمات مرور قوية منفصلة، ويُنشئ مدرسة وفصلًا وعلاقات تجريبية بينها. كما يؤكد بريد *هويات الاختبار فقط* إداريًا لأن النطاق المحجوز لا يستقبل رسائل. لتغيير نطاق الاختبار يمكن ضبط `CLAUDE_QA_EMAIL_DOMAIN` إلى نطاق اختبار تملكه.

**يحفظ بيانات الدخول في ملف خاص:** `~/.dadyoom-private/claude-qa-<run-id>.json` بامتياز 0600. لا تضع هذا الملف أو كلمات المرور أو مفتاح الخدمة في مستودع GitHub أو تطبيق واجهة أو محادثة عامة. شارك مع كلود بيانات حسابات الاختبار الأربعة فقط في جلسة خاصة موثوقة. مجرد إنشاء Pull Request أو دمجه **لا ينشئ** هذه الحسابات: يجب تشغيل `--apply`.

## بروتوكول اختبار كلود

- تسجيل الدخول من `https://dadyoom.com/login`، مع جلسة منفصلة لكل دور.
- **الطالب:** اختيار الدولة والصف، الدروس ومحتواها الفعلي، أهداف الدرس، الأنشطة والألعاب، الأسئلة والدرجات، متابعة التقدم وإعادة فتح الدرس، جودة RTL والجوال.
- **المعلم:** فتح الفصل التجريبي، متابعة الطالب التجريبي، الشرح والتحضير والواجبات والتقارير، الصلاحيات.
- **ولي الأمر:** ظهور الطالب المرتبط فقط، مقارنة تقارير التقدم قبل وبعد اختبار الطالب، متابعة الضعف والقوة، حالات عدم وجود بيانات.
- **المدرسة:** المدرسة التجريبية فقط، المعلم المرتبط، الفصل والطالب التجريبيان، التقارير والصلاحيات دون دخول لوحة مالك المنصة.
- **اختبار عزل الأدوار:** التوجه مباشرة إلى مسارات أدوار أخرى والتحقق من المنع أو إعادة التوجيه ومن عدم تسريب بيانات.
- **اختبار المناهج:** فصل وجود عنوان الدرس عن وجود الشرح الحقيقي؛ لا تُعلن مطابقة أي كتاب رسمي من دون مراجعته بحسب الدولة والصف والفصل والطبعة.

**الحدود:** لا تُفتح بيانات أشخاص حقيقيين، ولا تُجرى مدفوعات أو تحويلات، ولا يُعدل محتوى الدروس أو النشر أو إعدادات الأمان، ولا يُربط أي مستخدم حقيقي بكيانات الاختبار.

## برومبت جاهز لكلود

> أنت مدقق استخدام وأمن وتجربة تعليمية لمنصة ضاديوم. استخدم أربعة حسابات QA التي سأوفرها لك على انفراد (طالب، معلم، ولي أمر، مدرسة) وسجل الدخول لكل دور مستقلًا. افحص فقط بيانات QA الاصطناعية. اعمل تقريرًا لكل نقص يوضح: الدور، الرابط، الدولة، الصف، الفصل، خطوات إعادة الإنتاج، النتيجة المتوقعة والفعلية، درجة الخطورة P0–P3، ودليلًا لا يحتوي بيانات شخصية، والحل المقترح. فرّق بين عيب تقني مؤكد، ونقص محتوى درس مثبت بالكتاب الرسمي بطبعته، وتحسين اختياري، وأمر غير قابل للتحقق. اختبر الجوال وRTL والتنقل، وحفظ تقدم الطالب وانتقال الأثر إلى المعلم وولي الأمر والمدرسة، وعدم اختلاط صلاحيات المستخدمين. لا تدعِ فحص 22 دولة كاملة بلا مستندات ومقارنة مفصلة لكل دولة وصف وفصل.

## بعد انتهاء الاختبار

احفظ تقرير QA الخاص وخفّض أو عطّل وصول كل حسابات QA في Supabase Authentication → Users باستخدام معرّفات المستخدمين الأربعة المحفوظة في الملف الخاص؛ لا تمس حسابات أخرى. تأكد من إلغاء الجلسات، ومن تنظيف الصفوف الاصطناعية المرتبطة وفق السياسة المعتمدة. لا تتشارك ملف كلمات المرور مع جهة أخرى.

**التحقق:** السكربت يراجع إنشاء الملفات الشخصية وعلاقات المدرسة والفصل وولي الأمر من قاعدة البيانات. اختبار تسجيل الدخول إلى الموقع الحي وتصفح الواجهات لا يحدث حتى ينفذ المالك الأمر ويشغل جولة المتصفح.
