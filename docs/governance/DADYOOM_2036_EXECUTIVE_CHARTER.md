# Dadyoom 2036 International — Executive Charter

Status: proposed policy; **not deployed or enforced automatically**. Owner approval required for merge and deployment.

## North star
Dadyoom measures **verified improvement in what learners can do in Arabic**, not lesson counts, files, clicks, or video consumption. North-star metric: number of eligible learners demonstrating reliable improvement on comparable measures, with assessment coverage and uncertainty reported.

## Permanent delivery priorities
P0 Security > P1 DACF competency framework > P2 live learner growth passport / AGI > P3 adaptive learning > P4 Dad AI (ضاد) > P5 educational games. Never advance past an open blocking security gate.

## Roles
Student, Teacher, Parent, School Admin, Network Admin, Ministry Admin, Super Admin. All privilege grants require server-side authorized workflow, audit trail, and least privilege. Client profile fields are never authority.

## DACF
Domains: reading, reading comprehension, vocabulary, writing, spelling, syntax, morphology, written expression, oral expression, listening, conversation, rhetoric, literary appreciation, critical language thinking. Define observable behavior, levels, assessment blueprint, rubric, evidence, remedial and enrichment activities per leaf skill. Prevent overlapping domains from double-counting evidence. Map Bahrain grades 1–3 official topics first, then the other 22 Arab countries, with edition/source/reviewer provenance. International frameworks are mappings, not claims of official endorsement.

## Learner growth
Store baseline, current calibrated estimate, confidence, longitudinal evidence, strengths, gaps, and recommendations. AGI is **proposed and unvalidated**; no official growth claim until equated assessments, reliability/validity/fairness studies and uncertainty checks pass. Predictive risk and month-ahead forecasts require separate validation.

## Adaptive / Dad AI / games
Adapt sequence, challenge and intervention based on verified skill evidence. AI grades require teacher review when consequential; game XP cannot substitute for demonstrated mastery. Each feature must identify target DACF leaf skill, measurable outcome, data minimization and safety controls.

## Delivery lifecycle
Analysis -> design -> security review -> development in isolated branch -> security tests -> functional tests -> staging -> impact measurement -> gradual rollout -> monitoring -> full launch. Owner approval required before merge or deploy. Existing working functionality must not be broken; no new paid service without approval.

## Reporting template (every review)
- Current state: completed with evidence / in progress / not implemented or unverified
- Risks with severity and affected population
- Next single priority and blocking dependencies
- Executive decision: GO / NO-GO and why
- Links to PR, commit, test logs, coverage, staging and monitoring evidence
- Measurement of actual learning impact; distinguish baseline from target

## Ownership and constraints
Treat this as a governance proposal until reviewed. Never claim code tests, live security posture, backups, ministry endorsement, content completeness, or learning gains without direct evidence.
