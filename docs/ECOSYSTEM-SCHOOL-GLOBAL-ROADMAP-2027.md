# ضاديوم 2027 — خارطة المنظومة المدرسية والمدرسة الإلكترونية والمدرسة العالمية

**قرار البدء:** 2026-10-10  
**التاريخ المستهدف للمرحلة الأساسية من بيت اللغة العربية:** 2027-06-27 (هدف تخطيطي وليس ضمان إطلاق أو اعتماد).  
**الحالة:** مشروع تأسيسي منفصل عن الإنتاج؛ لا تُفعّل الميزات العامة قبل اجتياز بوابات الجودة.

## المبدأ الحاكم

ضاديوم «بيت اللغة العربية» هو المنتج الأول، وهو الأساس الذي يبني الثقة. لا تستبدله المدرسة ولا تؤخره. نطوّر ثلاثة مسارات بالتوازي على قاعدة تقنية مشتركة، ثم نطلقها بالتتابع. لا تُنشأ ثلاث قواعد بيانات منفصلة ولا منظومات هوية منفصلة دون سبب مثبت. لا تُنسخ صفحات أو خدمات موجودة بالفعل.

## إعادة استخدام ما هو قائم (مراجعة مستودع 2026-10-10)

- Next.js App Router وTypeScript مع Supabase SSR.
- المساحات القائمة `app/(dashboard)/school`, `teacher`, `student`, `parent`.
- مدرسة: `app/(dashboard)/school/classes`, `teachers`, `students`, `reports`, `meetings`.
- `features/school-link` و`features/classroom` و`features/student-classroom` و`features/live`.
- جداول/روابط موجودة بحسب migrations: `schools`, `school_teachers`, `teacher_classes`, `teacher_class_students`, `edu_live_sessions`.
- محرك المحتوى المرجعي القائم: countries -> curricula -> grades -> units -> lessons؛ يُستعمل للمسارات الوطنية والدولية بعد التحقق ولا يُنسخ.
- عدم افتراض اكتمال أي وظيفة لمجرد وجود صفحة أو جدول؛ كل عنصر يحتاج فحص سلوكه وأمانه واختبارات دوره.

## المسار 1: المنظومة المدرسية الذكية (Dadyoom School OS)

**هدف المستخدم:** يستطيع مدير مدرسة تشغيل مؤسسته مع دعم عربي افتراضي، ويمكن للمعلم والطالب وولي الأمر استخدام حساباتهم القائمة.

النطاق المرحلي: بيانات مدرسة وسنوات وفصول وشعب، دعوات أعضاء وصلاحيات، حضور/غياب، جدول حصص، تكليفات/تسليمات، اختبارات/درجات وتقارير، لقاءات المدرسة، إشعارات أولياء الأمور.

**MVP أول:** مدرسة اختبار واحدة، سنة دراسية واحدة، صف واحد وشعبتان، حسابات تجريبية لكل دور، جدول حصص وحضور وواجب واحد وتقرير ولي الأمر. يعاد استخدام صفوف `schools` والعضويات الموجودة بعد فحص RLS.

**معيار الإغلاق:** المدير لا يرى إلا مدرسته، والمعلم لا يرى إلا فصوله المخولة، وولي الأمر لا يرى إلا ابنه المرتبط، والطالب لا يمكنه تعديل الدرجات. اختبارات صلاحيات آلية لمسارات القراءة والكتابة.

## المسار 2: مدرسة ضاديوم الإلكترونية (Dadyoom Virtual School)

**الهدف:** برنامج تعلّم افتراضي منظم وليس مجرد بث فيديو.

يعاد استخدام School OS + المنهج + LiveKit + أدوات المعلم. تضاف الجدولة، لقاء الحصة، الواجب، متابعة الإنجاز، الحضور الفعلي، سجل مشاركة الطالب، تقييم وتغذية راجعة.

**MVP أول:** فصل عربي افتراضي تجريبي محدود التسجيل، بوجود معلم ومشرف؛ لا نعلن تسجيلًا مدرسيًا رسميًا أو شهادات معتمدة قبل تحقق المتطلبات التنظيمية.

**معيار الإغلاق:** تجربة مكتملة من التسجيل المصرح به إلى حضور درس وإرسال واجب وتصحيحه وظهور تقرير دقيق لولي الأمر؛ الحضور لا يعتمد فقط على فتح صفحة اللقاء.

## المسار 3: مدرسة ضاديوم العالمية (Dadyoom Global School)

**الهدف:** تجربة تعليم متعددة الدول واللغات يمكن توسيعها دوليًا على مراحل.

المكونات: واجهة عربية/إنجليزية مع مراعاة اتجاه النص، مسار العربية للناطقين وغير الناطقين، تقويم ومواعيد حسب المنطقة الزمنية، سياسة حماية القاصرين والخصوصية، نسخ مناهج وطنية/دولية مع أصول مرخصة، التحقق من مؤهلات المعلمين، وضوابط الدولة المستهدفة.

**الامتثال:** مصطلح «مدرسة معتمدة» أو منح شهادة رسمية محظور دون ترخيص واعتماد فعليين لكل نطاق قضائي. حتى ذلك الحين يكون المشروع برنامجًا أو أكاديمية تعلم غير معتمدة.

## الحدود الفنية والأمنية

1. لا تغييرات على الصفحة الرئيسية الحالية أو التسجيل أو أدوار المستخدمين أو بيانات الطلاب ضمن عمل التأسيس دون ضرورة واختبارات حماية.
2. لا تشغيل لمدفوعات حقيقية؛ استمرار وضع Sandbox/مجانية المنتج الأساسي حسب قرار المشروع، وأي نموذج تجاري لاحق يحتاج قرارًا منفصلًا.
3. حماية البيانات: RLS على كل جدول مدرسي/عضوية جديد، أقل الصلاحيات، سياسات واضحة للصور والتسجيلات والأطفال، وسجلات التدقيق لإجراءات الإدارة والدرجات.
4. لا يُستحدث مسار `edu_*` ثانٍ للمناهج الأساسية؛ نستخدم محرك curricula/grades/units/lessons.
5. الإصدار العام للميزات الجديدة من وراء feature flags وتعطيل افتراضي؛ لا تفعيل على الإنتاج بلا اختبارات الأدوار والهواتف وبناء الإنتاج وفحص OAuth.
6. قبل إضافة أي جدول: جرد المخطط والمهاجرات وتوثيق سبب الإضافة وخطة ترحيل غير مدمرة، وقياس توافق العزل بين المدارس.
