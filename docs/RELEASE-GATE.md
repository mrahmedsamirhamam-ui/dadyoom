
# ضاديوم — بوابة الإطلاق

لا تعتبر النسخة منشورة إلا بعد نجاح جميع هذه البوابات:

1. TypeScript.
2. ESLint بصفر أخطاء وصفر تحذيرات.
3. الاختبارات الآلية.
4. Production Build.
5. فحص Curriculum Packs.
6. فحص رحلة التعلم.
7. فحص المصدر النهائي.
8. Smoke Test على خادم Production محلي.
9. ضاد يرد فعلاً عبر المسار الحقيقي.
10. المسارات المحمية ترفض الزائر غير المسجل.
11. Google Provider مفعّل فعليًا، وليس مجرد زر في الواجهة.
12. عدم وجود أسرار أو Backups في Git.
13. robots وsitemap وmanifest تعمل.
14. نجاح git diff --check.
15. Commit وPush لا يحدثان قبل نجاح ما سبق.

## ما لا يفعله الكود وحده

- إنشاء Google OAuth Client داخل حساب Google Cloud.
- شراء أو اختيار الدومين.
- ربط الدومين بخدمة الاستضافة.
- إثبات ملكية الموقع داخل Google Search Console.

هذه إعدادات حسابات خارجية، لكنها شروط إطلاق وليست Features جديدة.

## تحقق مسار الإنتاج قبل دمج ميزات الفروع (2026-10-21)

- تحقّق من عنوان وخريطة المسارات وحالة النشر الفعلية في `https://dadyoom.com` قبل اعتماد أي دمج. نجاح GitHub CI أو Netlify deploy preview لا يعني وصول التغيير إلى دومين الإنتاج.
- عند وجود اختلاف بين واجهة فرع `main` والواجهة الحية (كما رُصد في أكتوبر 2026)، **أوقف الدمج بغرض النشر** حتى يُحدّد بدقة المستودع والفرع وSHA اللذان يشغّلان Cloudflare/Worker الحالي، ويُراجع الفرق لئلا يعيد نسخة قديمة أو يمحو أعمالًا أحدث.
- تتطلب صفحات التعلّم الجديدة فحص الرابط الحقيقي بعد النشر (HTTP 200 لا 401/404)، وفحص الحركة والصوت والتشكيل وRTL والمتصفح على الهاتف، ثم اعتماد المعلم قبل نسبتها إلى مسارات المنهج.
- لا تغيّر إعدادات النشر أو الاشتراكات أو البيئات المالية، ولا تستخدم أي خدمات مدفوعة أو overages دون موافقة صريحة.
