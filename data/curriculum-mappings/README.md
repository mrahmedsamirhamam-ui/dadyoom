# National Official Match ↔ Dadyoom Core

هذا المسار يحفظ **طبقة الربط** بين الهيكل الوطني الرسمي ومهارات/دروس Dadyoom Core.

## لماذا ليست المطابقة 1:1 دائمًا؟

الكتاب الوطني قد يحتوي درسًا نصيًا محددًا مثل قصة أو قصيدة أو نص أدبي، بينما Dadyoom Core يبني كفايات عامة مثل:

- تحليل الشعر
- تحليل النثر
- الفكرة الرئيسة
- القراءة النقدية
- السرد
- الكتابة
- القواعد

لذلك لا نقول إن نصًا وزاريًا «هو نفسه» درس Core ما لم يكن ذلك صحيحًا حرفيًا من حيث البنية والهدف.

## أنواع العلاقة

- `direct-skill`: الهدف الرسمي يطابق مهارة Core مباشرة.
- `supporting-skill`: Core يدعم جزءًا من أهداف الدرس الرسمي.
- `text-specific`: الدرس الرسمي قائم على نص/عمل محدد؛ ضاديوم لا يعيد نشر النص المحمي، بل يغطي مهارات تحليله.
- `review-bundle`: درس مراجعة رسمي تغطيه مجموعة من دروس Core.
- `unmapped`: لا توجد تغطية مناسبة بعد.

## حالات المراجعة

- `candidate`: اقتراح آلي أو أولي، غير معتمد.
- `reviewed`: تمت مراجعته تربويًا لكن لم يُغلق دليل المصدر بعد.
- `verified`: تم التحقق من المصدر والأهداف والربط.
- `rejected`: اقتراح غير صحيح.

## قاعدة الاعتماد

وجود Candidate أو تشابه عنوان **لا يجعل** الدولة National Official Match مكتملة.

الدولة لا تصبح `officialReady` إلا بعد:

1. مصدر وطني موثّق.
2. تغطية الصفوف المطلوبة.
3. تغطية الفصول/الترمات المطلوبة.
4. وحدات ودروس/موضوعات قابلة للتدقيق.
5. خرائط تغطية reviewed/verified.
6. عدم وجود فجوات وطنية غير معلنة.
7. `matchingStatus=complete`.
8. `verificationStatus=verified`.

## التشغيل

توليد مرشحات من قاعدة البيانات:

```powershell
npm run curriculum:match:official -- --country=BH --year=2026-2027
```

المخرجات تذهب افتراضيًا إلى:

`diagnostics/official-match/<country>-<year>-candidates.json`

هذه الملفات تشخيصية ولا تُعد اعتمادًا رسميًا.
